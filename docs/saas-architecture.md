# 可选托管版架构草案

JellyHere 开源版维持单人自托管、无需账户。仓库现已加入[JellyHub 托管试验](managed-pilot.md)：同一 Go 进程内的租户隔离、GitHub 登录、一次性扫码绑定、独立设备与 MCP 客户端令牌、撤销和本地持久化。开源部署使用运营者自己的域名。手机与电脑仍只需发起出站连接。当前限 100 个账户，尚非可大规模运营的 SaaS。

## 边界

| 能力 | 自托管版 | 未来托管版 |
| --- | --- | --- |
| 登录 | 不需要；管理员自行保管设备与 MCP 令牌 | GitHub OAuth 登录，邀请管理令牌继续兼容；重启后需重新登录 |
| 设备 | 一个实例可连接多台个人设备，设备 ID 由用户配置 | 按账户隔离；扫码票据 5 分钟有效且仅能兑换一次，App 自动保存连接 |
| 智能体 | 共享 MCP 令牌，客户端需明确选择设备 | 当前每个客户端独立令牌，限定设备与只读/控制范围，可单独撤销 |
| 数据 | 屏幕内容只通过 relay 转发，不持久化 | 默认仍不存截图、界面树或输入；只记录必要的连接与操作元数据 |
| 运营 | 用户负责服务器与域名 | 提供限额、计费、滥用防护和设备支持流程 |

## 最小服务拆分

1. **身份与配对服务**：用户登录后生成一次性设备配对码。手机明确展示账户与设备名，用户在手机上确认归属；服务器只保存设备公钥或等价的可轮换身份，不把长期主密钥打进 APK。
2. **连接网关**：校验设备与用户授权，维持 WSS 连接，以租户 ID 和设备 ID 路由。设备断线时立即返回离线，不把命令无限排队。支持网关横向扩容时，再加入连接目录或粘性路由。
3. **MCP 授权层**：智能体按账户授权，令牌限定设备、只读或测试控制范围，并可逐个撤销。所有写操作仍受手机端暂停和现有控制范围限制。
4. **管理页面**：显示设备在线状态、授权中的客户端、最近连接时间与撤销按钮。页面只展示元数据；远程画面需要手机当前在线和明确授权。

## 首版托管验证顺序

第一步已完成：独立托管模式与两个租户隔离、只读/控制客户端及撤销测试；第二步已加入 GitHub 登录、手机扫码绑定与管理页面。原环境变量驱动的自托管路径保持不变。下一步验证真实用户的登录和绑定成功率，再将账户、会话及票据迁入数据库，考虑多节点网关与计费。先面向少量开发者试用，量化连接数、流量、图片大小和支持成本，再决定套餐。

支付、下单等未来个人助理动作需要独立于开发测试权限的手机端确认协议：智能体只能准备草稿，最终动作由用户核对具体订单摘要后在手机上确认；取消、超时和撤销需在执行前生效。托管账户登录或 MCP 授权不能替代这一步。
