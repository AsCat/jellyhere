# 果冻 Android 端产品体验改版草案

状态：产品设计，供界面实现和真机评审使用。首版仍以 Android 开发测试为核心；后续个人助理能力按实际交付逐步加入。

## 产品定位与主路径

用户第一次使用只需要理解一件事：**把一台手机连接给自己选定的智能体，并能随时在手机上暂停。** 果冻角色是随手可触达的状态与控制入口，完整配置留在 App 首页。

1. 在电脑网页生成设备二维码；手机打开果冻，点“扫码连接”，核对服务器与设备空间后绑定。
2. App 用逐项状态卡引导开启 Android 无障碍服务。通知与后台运行按需提示；悬浮角色可选，不阻断设备接入。
3. 网页为 Codex 等客户端单独授权；手机首页显示“已连接”和“可暂停”。托管版在网页管理客户端令牌，自托管版使用自建 relay 的对应入口。
4. 开发者按需从悬浮角色运行“无线调试”等快捷操作；正在读屏或操作时，角色显示简短状态并提供暂停。

开源包不内置维护者域名、账号或令牌。扫码票据提供服务器地址；自托管安装也应生成同格式的二维码。未实现统一扫码前，手动填写入口保留在“高级连接”。

## 现状问题

当前悬浮菜单高约 365–413 dp，同时显示临时 HTTPS 授权码、两种生成口令、无线调试、暂停、撤销和隐藏。JellyHub 托管模式尚不使用该临时 HTTPS 授权，却仍展示口令入口。贴边时要点两次才能打开菜单；长按直接启动无线调试，不易发现，也容易误触。主界面把扫码、服务器凭据、权限、角色和测试口令放在同一长列表，新用户难以判断下一步。

## 悬浮角色：一层只放状态与控制

贴边或完整显示时，**单击角色均直接打开紧贴屏幕边缘的紧凑面板**；拖动仍用于换边。再次单击或点面板外关闭。长按不再默认执行会修改系统设置的动作；若未来支持长按快捷动作，须由用户在 App 中显式设置，且同一动作也能从可见菜单进入。

```text
┌ 果冻 · 已连接          × ┐
│ 当前空闲 / 正在查看屏幕   │
│ [暂停远程访问]            │  ← 唯一突出按钮
│ [无线调试]  [打开果冻]    │  ← 开发模式下的快捷入口
└──────────────────────────┘
```

面板默认不超过 220 dp 高，依角色所在侧靠边放置，避开屏幕中心；小屏或横屏时按可用空间调整位置。按钮触控区域至少 48 dp；贴边露出的视觉部分可以更小，但实际触控区域应满足可操作性且避免覆盖系统边缘手势。面板不显示屏幕文字、输入内容、设备令牌或四位口令。口令可在完整 App 的“访问与授权”页按需生成。

| 状态 | 面板首行 | 主操作 | 次操作 |
| --- | --- | --- | --- |
| 未绑定 | 尚未连接设备空间 | 打开果冻完成连接 | 无 |
| 连接中 / 离线 | 正在连接 / 连接中断 | 查看连接问题 | 打开果冻 |
| 在线空闲 | 已连接 · 当前空闲 | 暂停远程访问 | 已固定的快捷动作、打开果冻 |
| 正在读屏或操作 | 正在查看屏幕 / 正在点击 | 暂停后续操作 | 打开果冻 |
| 已暂停 | 远程访问已暂停 | 恢复远程访问 | 打开果冻 |

“暂停后续操作”立即阻止新请求；已提交给系统的手势可能还会完成。活动气泡继续保留在角色附近，只显示动作类型，短时间自动消失；面板由用户主动打开，不因新的状态通知抢焦点。读屏截图期间继续隐藏悬浮层。提供“收起到边缘”和“关闭悬浮角色”两个明确结果：前者为默认自动行为，后者在 App 的外观设置和面板更多入口中可找到。

### 开发快捷动作

首版只提供已实现且经过真机验证的动作，默认可固定一个到面板次操作位。开发测试预设为“打开无线调试”；执行后显示“正在查找设置 → 等待系统确认 → 已开启，端口 …”或具体失败原因。当前三星的本地悬浮路径尚未验收，验收前只显示“打开无线调试设置”，不承诺自动开启。未来动作库、点击路径经验和个人助理流程放在 App 的“快捷动作”页，不向首层菜单无限加行。

## App 首页：一屏看懂是否可用

采用按状态显示的单页卡片，而非把所有开关排成一个长列表：

1. **设备状态卡**：设备名、服务器类型、在线/离线、上次连接、无障碍授权、一个暂停/恢复按钮。未就绪时只突出当前缺失的下一步。
2. **连接与授权卡**：未绑定时主按钮“扫码连接”，次入口“连接自建服务器”；已绑定时显示设备空间与“管理智能体访问”。托管版跳转到对应网页，自托管版显示适用的授权方式；临时 HTTPS 口令仅在支持该能力的实例中出现。
3. **快捷动作卡**：无线调试、保持亮屏等开发工具；用户可选择一个固定到悬浮面板。动作执行结果和“需要手机解锁”等条件在这里说明。
4. **外观与高级设置**：角色选择、半隐藏、气泡、后台连接、诊断日志、手动连接配置和停止测试会话。敏感凭据不在普通首页露出。

首次安装先显示三步进度：“连接服务器 → 开启无障碍 → 设备在线”。扫码按钮才请求相机权限；悬浮角色开启时才解释其作用；后台连接遇到实际断线问题再提示省电设置。权限被拒绝时保留可继续浏览的界面并说明受影响功能。[Android 权限请求建议](https://developer.android.com/training/permissions/requesting)

## 托管、自托管与未来平台

设备端统一使用“扫码连接”“设备空间”“访问与授权”等中性文案；JellyHub 是一个可选托管服务名，不是 Android 能力名。不同部署只改变可用的连接与授权方式：托管版有 GitHub 登录与网页客户端授权；自托管版无需账户；不支持的功能不在悬浮菜单显示。iOS 与桌面端未来可以共用“设备状态、智能体授权、暂停”概念，但各平台快捷动作按能力声明决定，避免在界面里承诺不可用的跨 App 控制。

## 实施顺序与验收

| 阶段 | 范围 | 验收重点 |
| --- | --- | --- |
| P0 悬浮面板 | 单击即开、状态驱动、暂停优先、托管模式隐藏无效口令、开发快捷动作、长按不再直接操作 | 小米与三星竖屏/横屏/折叠屏；连接、暂停、远程操作中均能一眼识别状态；面板不遮住主要内容 |
| P1 首页与接入 | 状态卡、三步引导、分模式授权、设置分层、统一错误文案 | 新用户无文档完成扫码绑定和首次读屏；失败时知道下一步；自托管入口仍可找到 |
| P2 个性化与扩展 | 固定快捷动作、动作记录与可复用路径、能力驱动菜单 | 成功路径可复用但每次核对当前界面；不同设备与平台只显示可执行动作 |

先用 5 位未参与开发的 Android 开发者观察首次接入、暂停、恢复无线调试三项任务，记录完成率、耗时、误触和求助点；再在小米和三星上做实际遮挡与无障碍读屏验收。点击目标和菜单控件按 Android 建议至少提供 48 dp 的触控区域，并给按钮可读的无障碍描述。[Android 无障碍设计指南](https://developer.android.com/design/ui/mobile/guides/foundations/accessibility)
